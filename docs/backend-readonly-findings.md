# Backend Integration Findings

The frontend was aligned against `Repflow-backend` at revision `6c2e594` without modifying backend source. This document records the backend issues and contract limitations observed during that read-only review.

## Frontend compatibility implemented

The frontend uses bearer tokens returned by `POST /api/Auth/login`, derives the signed-in user identity from JWT claims, and then enriches that identity through `GET /api/Users/{id}` when available. This avoids assuming the backend provides a current-user endpoint.

The frontend now uses React Query clients for the authenticated feed, profile posts, communities, community posts, community challenges, challenge enrollment/progress, workout sessions, and physical-data personal records. The app sends the backend’s documented JSON field names for registration, password reset, community creation, posts, and challenge operations.

## Backend issues to resolve

| Severity    | Finding                                                                                                                                                                                      | Impact on frontend                                                                                                                                                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| High        | `Program.cs` contains no `AddCors` service registration or `UseCors` middleware.                                                                                                             | A frontend running on a separate browser origin, such as `http://localhost:8080`, cannot call the API directly. Use the local frontend proxy during development or add an explicit CORS policy in the backend deployment.            |
| High        | `AuthController` has no `GET /api/Auth/me` endpoint.                                                                                                                                         | The frontend cannot verify a session from the server using the endpoint originally anticipated; it falls back to decoding the JWT and fetching `GET /api/Users/{id}`.                                                                |
| Medium      | Registration sets `IsEmailVerified = true`, generates a verification token, and returns a message asking the user to check email, but no email delivery is implemented in the reviewed flow. | The frontend directs newly registered users to sign in rather than presenting a verification-code step.                                                                                                                              |
| Medium      | `CommunityController` uses leading slashes in `[HttpPost("/requests/{requestId}")]` and `[HttpGet("/name/{name}")]`.                                                                         | ASP.NET treats these as root routes (`/requests/...` and `/name/...`) rather than routes under `/api/Community`; community discovery and request approval were not wired into the frontend because their API paths are inconsistent. |
| Medium      | There is no endpoint to list all discoverable communities.                                                                                                                                   | The frontend can show the signed-in user’s communities and create/join known communities, but cannot provide a backend-driven global discovery directory.                                                                            |
| Medium      | `PostResponseDto` exposes only an `AuthorId`, without the author name or avatar.                                                                                                             | Feed and community post cards use a neutral member label and an ID-derived handle unless a richer user endpoint is added or posts are enriched server-side.                                                                          |
| Product gap | No run-specific API appears in the reviewed controller inventory.                                                                                                                            | The existing Runs screen remains a separate static product surface and is not presented as backend-backed activity data.                                                                                                             |

## Deployment configuration

For development, leave `VITE_API_BASE_URL` unset so the frontend sends requests to `/api` and the configured Vite proxy forwards them to the backend. For any deployed frontend, set `VITE_API_BASE_URL` to the backend origin and configure backend CORS to permit the exact frontend origin plus the `Authorization` header.
